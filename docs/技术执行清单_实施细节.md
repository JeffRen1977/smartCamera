## 零、开发环境与执行顺序（Mac 先行、Ubuntu 后续）

若当前在 **macOS** 上开发，可先完成模型开发与量化流水线框架，待有 **Ubuntu 20.04** 或 RB5 设备后再完成 SNPE 量化与边缘部署。

### 0.1 分阶段执行建议

| 阶段 | 环境 | 任务 | 说明 |
|------|------|------|------|
| **模型开发** | Mac | 训练、导出 ONNX | Ultralytics、PyTorch 等可在 Mac 上完成 |
| **API 开发与联调** | Mac | HAL、mock 适配器 | 使用 `backend="mock"` 验证流程 |
| **量化流水线框架** | Mac | CLI、校验逻辑、TensorRT 脚本 | 量化脚本可先搭建结构 |
| **SNPE 量化** | Ubuntu / Docker | ONNX → DLC | SNPE SDK 仅支持 Linux/Windows，需 Ubuntu 或 Docker |
| **边缘推理** | Ubuntu + RB5/Jetson | 真实硬件验证 | 在目标设备上安装 SDK、部署 DLC/Engine |

### 0.2 当前可优先完成的工作（Mac）

1. **模型**：在 Mac 上训练或导出 YOLOv8n 至 ONNX
2. **HAL**：实现并测试统一 API、mock 适配器
3. **量化**：实现 `quantize` CLI 框架、ONNX 校验、TensorRT 部分（Mac 可安装 TensorRT）
4. **校准数据**：准备 100–500 张代表性图像，供后续 INT8 量化使用

### 0.3 后续在 Ubuntu 上完成的工作

1. 安装 SNPE SDK（2.2.1 节）
2. 执行 ONNX → DLC 转换及 INT8 量化
3. 将 DLC 拷贝至 RB5，验证 SNPE 适配器推理
4. 编写 EDS / Modbus 寄存器映射等 PLC 集成配置

## 一、优先级 P0：统一感知 API 规范

### 1.1 目标

定义 AI 容器与底层推理引擎之间的**标准接口**，使上层算法容器仅调用该接口，无需关心底层为 SNPE 或 TensorRT。接口需覆盖：图像输入、推理启动、结果输出格式、I/O 控制。

### 1.2 API 接口定义

#### 1.2.1 初始化

| 接口 | 签名 | 说明 |
|------|------|------|
| `init()` | `PerceptionAPI(backend=None)` | 可选 `backend`；不指定时自动检测平台 |
| 自动检测逻辑 | 读取 `/proc/device-tree`、CPU 信息 | 识别 Qualcomm / NVIDIA / 其他平台 |
| 环境变量覆盖 | `HAL_BACKEND=snpe|tensorrt|openvino` | 强制指定后端 |

#### 1.2.2 推理接口

| 接口 | 签名 | 说明 |
|------|------|------|
| 同步推理 | `infer(image_raw, model_id) -> result` | 阻塞直至返回结果 |
| 异步推理 | `infer_async(image_raw, model_id, callback)` | 高吞吐场景，通过回调返回 |
| 模型加载 | `load_model(model_id, model_path)` | 懒加载，首次 `infer` 时自动调用 |

**参数约定**：

- `image_raw`：`numpy.ndarray` (H, W, C) 或 `bytes`，支持 RGB/BGR，H/W 由模型要求决定
- `model_id`：字符串，如 `yolov8n_defect`，内部映射为实际模型路径

#### 1.2.3 I/O 控制（可选）

| 接口 | 签名 | 说明 |
|------|------|------|
| 设置输出 | `set_io(pin, value)` | 简单 GPIO 触发（如报警灯、蜂鸣器） |
| 获取图像源 | `get_image_source(stream_id)` | 获取指定相机/视频流句柄 |

### 1.3 数据格式规范

#### 输入

| 格式 | 类型 | 说明 |
|------|------|------|
| 图像 | `np.ndarray` (H,W,C) uint8 | C=3 RGB 或 BGR，由模型要求 |
| 备选 | `bytes` (JPEG/RAW) | 由 API 层解码为 ndarray |

#### 输出（统一结构）

```json
{
  "detections": [
    {
      "class_id": 0,
      "class_name": "hard_hat",
      "confidence": 0.92,
      "bbox": [x1, y1, x2, y2],
      "extra": {}
    }
  ],
  "metadata": {
    "inference_time_ms": 12.5,
    "model_id": "yolov8n_defect",
    "backend": "snpe",
    "image_shape": [640, 640, 3]
  }
}
```

- `detections`：检测框列表；无检测时为空数组
- `metadata`：推理耗时、模型 ID、后端名称等

### 1.4 预处理与后处理职责划分

| 阶段 | 负责层 | 说明 |
|------|--------|------|
| 归一化 / Resize | API 层 | 根据模型要求统一处理 |
| 推理 | 适配器 | 仅执行推理，输出 raw tensor |
| NMS / 解码 | API 层 | 统一后处理逻辑，适配器不参与 |
| 错误码 | 适配器 | 返回明确错误码供调试 |

### 1.5 错误码约定

| 错误码 | 含义 |
|--------|------|
| `OK` | 成功 |
| `MODEL_NOT_LOADED` | 模型未加载或路径无效 |
| `INVALID_INPUT` | 图像格式或尺寸错误 |
| `INFERENCE_FAILED` | 推理执行失败 |
| `BACKEND_UNAVAILABLE` | 指定后端不可用 |

### 1.6 接口示例（Python）

```python
from hal import PerceptionAPI

api = PerceptionAPI(backend="snpe")  # 或 None 自动检测
result = api.infer(image, model_id="yolov8n_defect")
# result: {"detections": [...], "metadata": {"inference_time_ms": 12, ...}}
```

### 1.7 接口示例（C++）

```cpp
#include "hal/perception_api.h"

auto api = PerceptionAPI::Create(/* backend */);
auto result = api->Infer(image, "yolov8n_defect");
```

## 二、优先级 P0：构建 SNPE 和 TensorRT 适配器原型

### 2.1 硬件采购清单

| 平台 | 型号 | 用途 | 备注 |
|------|------|------|------|
| Qualcomm | RB5 (QRB5165) | SNPE 验证 | 可选 QS610/QS6490 作为量产目标 |
| NVIDIA | Jetson Orin Nano 或 Xavier NX | TensorRT 验证 | 或 Jetson Orin NX 提升算力 |

### 2.2 软件环境准备

#### 2.2.1 高通 RB5 (SNPE)

| 项目 | 版本/要求 |
|------|-----------|
| 系统 | Ubuntu 20.04 / 22.04 / Yocto（**SNPE 不支持 macOS**，仅 Linux x86_64 / Windows） |
| SNPE SDK | 2.x（Qualcomm Neural Processing SDK） |
| Python | 3.8+ |
| 模型格式 | DLC（由 snpe-onnx-to-dlc 转换） |

**环境说明**：
- **macOS 用户**：可先在 Mac 上完成模型开发与 ONNX 导出；SNPE 量化与推理需在 **Ubuntu** 或 **Docker (Ubuntu 镜像)** 中执行
- **RB5 推理**：DLC 在 Ubuntu 上生成后，拷贝至 RB5 设备运行

**下载 SNPE**：

1. 访问 [Qualcomm Neural Processing SDK](https://developer.qualcomm.com/software/qualcomm-neural-processing-sdk)（需 Qualcomm Developer 账号）
2. 下载对应 Ubuntu 版本的 Linux x86_64 包（如 `snpe-2.x.x.zip`）
3. 解压：`unzip snpe-*.zip -d ~/snpe`

**Ubuntu 安装步骤**：

```bash
# 1. 设置 SNPE 根目录
export SNPE_ROOT=~/snpe/snpe-2.x.x
echo 'export SNPE_ROOT=~/snpe/snpe-2.x.x' >> ~/.bashrc

# 2. 安装依赖（在 SNPE 根目录下执行）
cd $SNPE_ROOT
source bin/dependencies.sh
source bin/check_python_depends.sh

# 3. 添加 SNPE 工具到 PATH
export PATH=$SNPE_ROOT/bin/x86_64-linux-clang:$PATH
export LD_LIBRARY_PATH=$SNPE_ROOT/lib/x86_64-linux-clang:$LD_LIBRARY_PATH
```

**Python 包**（可选，用于 Python 推理）：

```bash
cd $SNPE_ROOT
pip install -r lib/python/requirements.txt
pip install lib/python/wheels/snpe-*.whl  # 如 snpe-2.15.0.230725-cp38-cp38-linux_x86_64.whl
```

**Docker 方式（Mac 用户）**：

```bash
# 启动 Ubuntu 容器，挂载项目目录，在容器内安装 SNPE
docker run -it --rm -v $(pwd):/workspace ubuntu:20.04 bash
# 容器内：apt update，按上述步骤安装 SNPE
```

**ONNX → DLC 转换**：

```bash
# FP32 DLC
$SNPE_ROOT/bin/x86_64-linux-clang/snpe-onnx-to-dlc \
  --input_network model.onnx \
  --output model.dlc

# INT8 量化（需先有 FP32 DLC）
$SNPE_ROOT/bin/x86_64-linux-clang/snpe-dlc-quantize \
  --input_dlc model.dlc \
  --input_list calibration_images.txt \
  --output_dlc model_int8.dlc
```

**关键文件路径**（安装后）：
- 运行库：`$SNPE_ROOT/lib/x86_64-linux-clang/`（`libSNPE.so`、`libSnpeDspRuntime.so` 等）
- 转换器：`$SNPE_ROOT/bin/x86_64-linux-clang/snpe-onnx-to-dlc`
- 量化器：`$SNPE_ROOT/bin/x86_64-linux-clang/snpe-dlc-quantize`

#### 2.2.2 NVIDIA Jetson (TensorRT)

| 项目 | 版本/要求 |
|------|-----------|
| 系统 | JetPack 5.x / 6.x |
| TensorRT | 随 JetPack 预装 |
| Python | 3.8+ |
| 模型格式 | Engine (由 TensorRT Builder 构建) |

**关键步骤**：

1. 使用 `trtexec` 或 Python API 将 ONNX 转为 Engine
2. 支持 FP16/INT8 量化
3. 首次运行需构建 Engine，可缓存到磁盘加速后续启动

### 2.3 参考模型：YOLOv8n

| 属性 | 值 |
|------|-----|
| 模型 | YOLOv8n (ultralytics) |
| 输入 | 640×640×3, FP32 或 INT8 |
| 输出 | 检测框 + 类别 + 置信度 |
| 导出 | `model.export(format="onnx")` |

**模型规格**：

| 规格 | 参数量 | 算力需求 | 推荐场景 |
|------|--------|----------|----------|
| YOLOv8n | 3.2M | 最低 | 边缘设备、RB5、Jetson Nano |
| YOLOv8s | 11.2M | 低 | 平衡精度与速度 |
| YOLOv8m | 25.9M | 中 | 更高精度 |
| YOLOv8l / x | 43.7M / 68.2M | 高 | 云端或高算力边缘 |

**预训练权重**：默认 COCO 80 类；可从 [Ultralytics](https://github.com/ultralytics/ultralytics) 自动下载 `yolov8n.pt`。

**导出 ONNX**（可在 Mac / Windows / Linux 上执行）：

```bash
# 基本导出（imgsz 默认 640）
yolo export model=yolov8n.pt format=onnx imgsz=640

# 推荐参数：固定输入、简化图、指定 opset
yolo export model=yolov8n.pt format=onnx imgsz=640 dynamic=False simplify=True opset=12

# Python 方式
from ultralytics import YOLO
model = YOLO("yolov8n.pt")
model.export(format="onnx", imgsz=640, opset=12, simplify=True, dynamic=False)
```

**导出参数说明**：

| 参数 | 说明 | 建议 |
|------|------|------|
| `imgsz` | 输入尺寸 (H, W) | 640 或 (640, 640) |
| `opset` | ONNX opset 版本 | 12（SNPE/TensorRT 兼容较好） |
| `dynamic` | 动态 batch/尺寸 | False（边缘部署建议固定） |
| `simplify` | ONNX 图简化 | True（减少冗余算子） |
| `half` | FP16 导出 | 可选，目标支持 FP16 时启用 |

**输入预处理**：
- 归一化：`/255.0`（若模型训练时未内置）
- 通道顺序：RGB 或 BGR（需与训练一致）
- Letterbox：保持宽高比缩放，不足处填充灰边

**输出格式**（YOLOv8 ONNX）：
- Shape：`(1, 84, 8400)` — 4 坐标 + 80 类置信度，8400 个候选框
- 后处理：解析为 `[x_center, y_center, w, h]` + 类别 + 置信度，经 NMS 过滤

**自定义训练**（工业场景）：
- 使用 Ultralytics 在自己数据集上微调：`model = YOLO("yolov8n.pt"); model.train(data="coco128.yaml", epochs=100)`
- 导出时使用训练好的 `runs/detect/train/weights/best.pt` 替换 `yolov8n.pt`

### 2.4 适配器实现要点

#### 2.4.1 基类接口（适配器需实现）

```python
class BaseAdapter(ABC):
    @abstractmethod
    def load_model(self, model_id: str, model_path: str) -> None: ...

    @abstractmethod
    def infer(self, image: np.ndarray) -> dict: ...

    @abstractmethod
    def get_supported_formats(self) -> list[str]: ...
```

#### 2.4.2 SNPE 适配器核心流程

1. 加载 DLC：`snpe.load_from_dlc(path)`
2. 设置输入：`set_input_tensor(name, data)`
3. 执行：`execute()`
4. 获取输出：`get_output_tensor(name)`
5. 转换为统一输出格式

#### 2.4.3 TensorRT 适配器核心流程

1. 反序列化 Engine 或从 ONNX 构建
2. 创建执行上下文
3. 拷贝输入到 GPU
4. `execute_v2()`
5. 拷贝输出，转换为统一格式

### 2.5 验证目标与验收标准

| 项目 | 标准 |
|------|------|
| 双板运行 | 同一 YOLOv8n 模型在 RB5 和 Jetson 上均可通过 `infer(img, "yolov8n")` 运行 |
| 输出一致 | 相同输入图像，两板输出格式统一（detections + metadata） |
| 性能 | 记录推理耗时，作为后续优化基线 |
| 切换 | 通过 `HAL_BACKEND=snpe` 或 `tensorrt` 切换后端，无需改业务代码 |

## 三、优先级 P1：模型优化自动化工具 (Quantization Pipeline)

### 3.1 目标

- **输入**：ONNX 模型
- **输出**：适配 SNPE 的 INT8 DLC、适配 TensorRT 的 Engine
- **形态**：PC 端 CLI 或脚本
- **后续**：量化产物打包进 Docker 镜像，供边缘拉取

### 3.2 工具链选型

| 目标 | 工具 | 输入 | 输出 |
|------|------|------|------|
| Qualcomm | SNPE DLC Converter | ONNX | DLC (FP32/INT8) |
| NVIDIA | TensorRT (trtexec / Python) | ONNX | Engine (FP16/INT8) |
| Xilinx K26 | Vitis AI (后续 P2) | ONNX | Xmodel |
| Rockchip | RKNN-Toolkit2 (后续 P2) | ONNX | RKNN |

### 3.3 SNPE 量化流程

#### 3.3.1 环境

- PC：x86_64 **Linux / Windows**，安装 SNPE SDK（SNPE 不支持 macOS）
- Mac 用户：可使用 Docker 运行 Ubuntu 镜像，在容器内安装 SNPE 并执行 ONNX→DLC 转换
- Python 脚本调用 `snpe-dlc-converter` 或 `snpe-onnx-to-dlc`

#### 3.3.2 步骤

1. **转换 ONNX → DLC (FP32)**  
   ```bash
   snpe-onnx-to-dlc --input_model model.onnx --output_model model.dlc
   ```

2. **INT8 量化（需校准数据）**  
   - 准备 100–500 张代表性图像作为校准集
   - 使用 `snpe-dlc-quantize` 或 Python 脚本
   ```bash
   snpe-dlc-quantize --input_dlc model.dlc --input_list calibration_images.txt --output_dlc model_int8.dlc
   ```

3. **验证**  
   - 在目标设备上运行推理，对比 FP32 与 INT8 精度（mAP、召回率）

#### 3.3.3 校准数据格式

- `calibration_images.txt`：每行一个图像路径
- 图像需与推理时输入尺寸一致（如 640×640）

### 3.4 TensorRT 量化流程

#### 3.4.1 环境

- PC：安装 CUDA + TensorRT（或使用 Docker 镜像 `nvcr.io/nvidia/tensorrt`）
- 目标设备：Jetson 上可直接构建，或 PC 构建后拷贝 Engine

#### 3.4.2 步骤

1. **FP16 构建（快速验证）**  
   ```bash
   trtexec --onnx=model.onnx --saveEngine=model_fp16.engine --fp16
   ```

2. **INT8 构建（需校准）**  
   - 实现 `IInt8EntropyCalibrator2` 接口，提供校准数据
   - 或在 Python 中使用 `trt.Builder` 配置 INT8
   ```bash
   trtexec --onnx=model.onnx --saveEngine=model_int8.engine --int8 --calib=calibration.cache
   ```

3. **验证**  
   - 对比 FP32/FP16/INT8 精度与延迟

### 3.5 CLI 设计

```bash
# 通用调用
quantize --model model.onnx --target snpe --output model.dlc [--int8] [--calib-dir ./calib]
quantize --model model.onnx --target tensorrt --output model.engine [--fp16|--int8] [--calib-dir ./calib]

# 示例
quantize --model yolov8n.onnx --target snpe --output yolov8n.dlc --int8 --calib-dir ./calib_images
quantize --model yolov8n.onnx --target tensorrt --output yolov8n.engine --fp16
```

### 3.6 Pipeline 步骤（自动化脚本）

1. **校验 ONNX**：检查 opset、输入输出、动态 shape
2. **按 target 选择工具**：snpe / tensorrt
3. **执行量化**：FP32→DLC/Engine，可选 INT8
4. **精度验证**（可选）：在验证集上跑推理，输出 mAP
5. **打包**：将 DLC/Engine 与推理代码打包进 Docker 镜像

### 3.7 Docker 打包

```
# 示例：将量化产物打入镜像
FROM hal-runtime:latest
COPY yolov8n.dlc /models/yolov8n_defect.dlc
# 或
COPY yolov8n.engine /models/yolov8n_defect.engine
```

- 不同 target 产出不同镜像：`scene-defect:snpe-rb5`、`scene-defect:tensorrt-jetson`
- 边缘设备根据 `HAL_BACKEND` 拉取对应镜像

### 3.8 目录结构

```
src/03_orchestration/
└── quantization/
    ├── quantize.py          # CLI 入口
    ├── snpe/
    │   ├── onnx_to_dlc.py
    │   └── quantize_int8.py
    ├── tensorrt/
    │   ├── onnx_to_engine.py
    │   └── calibrate.py
    ├── common/
    │   ├── validate_onnx.py
    │   └── accuracy_check.py
    └── calib/               # 校准数据目录（.gitignore）
```

### 3.9 验收标准

| 项目 | 标准 |
|------|------|
| ONNX 输入 | 接受标准 YOLOv8n ONNX |
| SNPE 输出 | 生成可在 RB5 上运行的 DLC（FP32 或 INT8） |
| TensorRT 输出 | 生成可在 Jetson 上运行的 Engine（FP16 或 INT8） |
| CLI | 单条命令完成转换，支持 `--int8` 与 `--calib-dir` |
| 打包 | 量化产物可复制进 Docker 镜像并成功拉取运行 |
